##### Motivation
Many people own large music collections and still pay for a streaming service, because the streaming experience is simply better. Self-hosted streaming apps like Plex and Jellyfin exist, but they're built around movies and TV, with music as an afterthought. Purpose-built options like Navidrome handle libraries well but feel dated and lack features that people have come to expect from a modern music app: instant search and access, a convenient queue, offline playback, and actually useful recommendations. Users must choose between paying a monthly fee for a commercial service, abandoning their expensive, curated personal collection or getting an inconvenient and subpar experience from a self-hosted app.
##### Approach
I propose a self-hosted music streaming platform that gives users a modern, extensible listening experience built on their own collection. The system has three crucial parts: a server container image, a set of clients for web and mobile, and a plugin interface that lets the community extend both. The server manages the library. It scans and indexes files on disk, normalizes metadata, maintains a search index built for prefix and fuzzy matching, transcodes on demand, and records playback history. It exposes an HTTP API for both first-party and third-party clients. A smart recommendation system is central, building recommendations from listening history and content similarity derived from audio features. The various clients allow users to listen on any device with a snappy experience, including a queue users can reorder and add to quickly, with queue and playback state synced across devices. An equally good offline experience is critical; many users want their own collections synced to their devices for listening at any time, anywhere. The plugin system provides stable extension points on both server and client: metadata providers, scrobbling targets, lyrics and artwork sources, alternate recommendation strategies, and import tools.
##### Challenges
The recommendation system is the hardest part of the project and the most likely to determine whether the result feels up to the quality of commercial services like Spotify. Without usage data from millions of listeners, quality has to come from audio analysis and open datasets, and evaluating whether a recommendation is good is inherently subjective. Designing an evaluation method and optimizing recommendations are going to be a good chunk of the work. Instant access makes every new feature harder to implement and optimize. Search must return results as the user types over a library that could hold hundreds of thousands of tracks. Playback has to begin within a few hundred milliseconds, which means building in prefetching, range requests, smart caching, and fast on-the-fly transcodes. Gapless playback and offline sync each add more complications, and mobile clients must integrate with platform media frameworks to behave correctly on a lock screen or in a car. Some connected features like remote control require realtime interactions between clients and the server, adding more complexity. Creating a plugin system also adds complications to each layer of the app. It requires building hooks into each part of the program and designing security controls around what plugins can access or change.
##### Success
Success means a user can deploy the server in a few minutes, point it at their files, and use it as their primary listening app without missing a commercial service. Search and playback must stay responsive with massive libraries of hundreds of thousands of tracks. Recommendations must be good enough that users actually play them, rather than ignoring them.
